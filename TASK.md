# Ticks to Bars Converter
Утиліта для перетворення тіків в бари.

## Завдання
- Створити утиліту для перетворення тіків в бари.
- Вхідні параметри можуть бути введені через файл конфігурації або через аргументи командного рядка (вищий пріоритет).
- Прогресс-бар повинен бути виведений в консоль.
- Документація повинна бути написана англійською мовою.
- Код повинен бути структурований, добре організований і покритий тестами.
- Утиліта повинна бути скомпільована для Linux, MacOS та Windows.

## Інстументи
- Go 1.xx (імплементація)
- Toml (конфігурація)
- Makefile (збірка)

## Обмеження
- Утиліта працює з файлами в форматі CSV.
- Утиліта працює з таймфреймами від 1 секунди до років.

## Конфігурація
Файл конфігурації `ticks2bars.toml` повинен мати наступний вигляд:
```toml
[config]
input_dir = "ticks" # директорія для файлів тіків, --input-dir=ticks
output_dir = "bars" # директорія для збереження барів, --output-dir=bars

symbols = "EURUSD,GBPUSD,XAUUSD,NAS100" # символи, --symbols=EURUSD,GBPUSD,XAUUSD,NAS100
timeframes = "1m,3m,5m,15m,1h,4h,1D,1W,1M" # таймфрейми, --timeframes=1m,3m,5m,15m,1h,4h,1D,1W,1M
include_header = false # включати заголовок в файли барів, --include-header=false
ticks_timestamp_layout = "2006.01.02 15:04:05.000" # формат timestamp у файлах тіків, --ticks-timestamp-layout=2006.01.02 15:04:05.000
bars_timestamp_layout = "2006-01-02 15:04:05" # формат timestamp у файлах барів, --bars-timestamp-layout="2006-01-02 15:04:05"

workers = 999 # кількість робочих потоків (значення: 1,2,3...999), --workers=999
force = false # перезаписати вже існуючі бари, --force=false
progress_bar = true # показувати прогрес-бар, --progress-bar=true
```

## Команди
- `--help` - показати довідку.
- `--version` - показати версію.
- `--convert` - перетворити тіки в бари.
- `--clean` - очистити всі файли в директорії `output_dir`.

Кожна команда може приймати додаткові параметри.

## Тип файлів
Файли тіків мають формат:
```csv
<TIMESTAMP>,<BID>,<ASK>
```
- `TIMESTAMP` - timestamp
- `BID` - ціна Bid
- `ASK` - ціна Ask

Наприклад:
```csv
timestamp,bid,ask
2003.05.05 03:00:05.536,1.12161,1.12177
2003.05.05 03:00:06.561,1.12166,1.12182
2003.05.05 03:00:14.085,1.12163,1.12183
2003.05.05 03:00:14.420,1.12173,1.12183
2003.05.05 03:00:15.110,1.12170,1.12190
```

Файли барів мають формат:
```csv
<TIMESTAMP>,<OPEN>,<HIGH>,<LOW>,<CLOSE>
```
- `TIMESTAMP` - timestamp
- `OPEN` - ціна відкриття
- `HIGH` - максимальна ціна
- `LOW` - мінімальна ціна
- `CLOSE` - ціна закриття

Наприклад:
```csv
timestamp,open,high,low,close
2003-05-05 03:00:00,1.12169,1.12316,1.12161,1.12266
2003-05-05 04:00:00,1.12237,1.12268,1.12109,1.12145
2003-05-05 05:00:00,1.12151,1.12218,1.12098,1.12160
2003-05-05 06:00:00,1.12130,1.12186,1.12059,1.12172
2003-05-05 07:00:00,1.12103,1.12180,1.12081,1.12124
```

Примітки:
- timestamp - це час брокера.
- timestamp для тіків і барів описується в конфігурації.

## Конвенції
Файли тіків мають таку конвенцію імен: `<SYMBOL>_ticks.csv` (наприклад: EURUSD_ticks.csv).
- `SYMBOL` - символ

Файли барів мають таку конвенцію імен: `<SYMBOL>_<TIMEFRAME>.csv` (наприклад: EURUSD_1m.csv).
- `SYMBOL` - символ
- `TIMEFRAME` - таймфрейм

Хедер в файлі тіків завжди пропускається, якщо він існує.

Кількість знаків після крапки в ціні барів (`digits`) має бути такою ж, як і в цінах тіків з першого цінового рядка.

Ціна OHLC має бути розрахована на основі цін Bid і Ask:
- `OPEN = (Bid + Ask) / 2` першого тіка
- `HIGH = MAX(Bid, Ask)` від максимальної ціни по всіх тіках бару
- `LOW = MIN(Bid, Ask)` від мінімальної ціни по всіх тіках бару
- `CLOSE = (Bid + Ask) / 2` останнього тіка

Ціни OHLC округлюються до `digits` знаків після крапки.

Маркер таймфрейму являє собою останній символ у його назві.
Існує декілька варіантів маркерів таймфреймів:
- `s` - секунда (межі: 1-59, бо 60 секунд це хвилина)
- `m` - хвилина (межі: 1-59, бо 60 хвилин це година)
- `h` - година (межі: 1-23, бо 24 години це день)
- `D` - день (межі: 1-27, бо 28-31 день це місяць)
- `W` - тиждень (межі: 1-3, бо 4 тижні це місяць)
- `M` - місяць (межі: 1-11, бо 12 місяців це рік)
- `Y` - рік (межі: 1-9999, бо 10000 рік це епоха)

Регістр має значення. Утиліта валідує маркер таймфрейму і завершує роботу з помилкою, якщо він не відповідає вимогам.
Число перед маркером обов'язкове, інакше утиліта завершує роботу з помилкою.

Для таймфреймів `D`, `W`, `M` і `Y` початок відліку визначається окремо:
- `D` - початок дня - 00:00:00.000
- `W` - початок тижня - понеділок
- `M` - початок місяця - 1 число
- `Y` - початок року - 1 січня

## Архітектура
Програма складається з трьох основних компонентів:
- Головний потік програми.
- Робочі потоки.
- Черга.

Спочатку перевіряється валідність вхідних параметрів та конфігурації.
Якщо є невідповідність, то утиліта завершує роботу і виводить повідомлення про помилку.

Перевіряється, чи існує директорія `output_dir` і чи є вона доступною для запису.
Якщо директорія не існує, то утиліта створює її.
Якщо директорія існує, але не є доступною для запису, то утиліта виводить повідомлення про помилку і завершує роботу.

Далі створюється список комбінацій символів і таймфреймів для перетворення.
Наприклад, для `symbols = "EURUSD,GBPUSD"` і `timeframes = "15m,1h"` буде створено список комбінацій:
```json
[
    {
        "symbol": "EURUSD",
        "timeframe": "15m"
    },
    {
        "symbol": "EURUSD",
        "timeframe": "1h"
    },
    {
        "symbol": "GBPUSD",
        "timeframe": "15m"
    },
    {
        "symbol": "GBPUSD",
        "timeframe": "1h"
    }
]
```

Кожна комбінація символ + таймфрейм:
- Має бути унікальною.
- Сортується в порядку зростання таймфрейму.
- Обробляється головним потоком послідовно (починаючи з найменшого таймфрейму).

Якщо файлу тіків для потрібного символу не існує - утиліта виводить про це повідомлення у вигляді помилки і продовжує роботу з наступним символом (якщо він був заданий).

Перед початком роботи отримується інформація про вже існуючі бари в директорії `output_dir` для потрібного символу і таймфрейму.
Якщо файл існує і `force = false`, то утиліта завершує роботу, виводить ім'я файлу і повідомлення про те, що файл вже існує.
Якщо файл існує і `force = true`, то утиліта виконує роботу і перезаписує файл.

Утиліта працює ефективно, не виконуючи зайву роботу.
Для цього:
- Таймфрейми сортуються в порядку зростання.
- Спочатку визначається найменший таймфрейм і перевіряється, чи існує файл барів для нього.
- Якщо потрібний таймфрейм кратний вже існуючому файлу меншого таймфрейму, то утиліта перетворює бари меншого таймфрейму в бари більшого таймфрейму.
- Якщо потрібний таймфрейм не кратний жодному існуючому файлу барів меншого таймфрейму, то утиліта перетворює тіки в бари для цього таймфрейму.

Процес перетворення даних в бари повинен бути багатопотоковим.
Значення `workers = 999` означає, максимальну кількість робочих потоків, яка може бути встановлена.
Реальна максимальна кількість робочих потоків буде дорівнювати кількості ядер процесора мінус один (залишивши один для головного потоку).

Для кожного символу, враховуючи таймфрейм, головний потік програми створює список чанків (`chunk_list`), який розбиває дані на частини (`chunk`).
Чанк містить інформацію про свою частину даних:
- символ (`symbol`)
- таймфрейм (`timeframe`)
- номер чанку (`chunk_number`)
- початковий зсув у байтах початкового файлу (`start_offset`)
- кінцевий зсув у байтах початкового файлу (`end_offset`)

Вирівнювання чанків повинно бути по межі бару (усі тіки одного timestamp-інтервалу в одному чанку), тобто щоб в один чанк входив як мінімум один цілий бар.
В різних чанках не може бути однакових timestamp.
Значення `start_offset` і `end_offset` не ріжуть CSV-рядок посередині, а йдуть по рядках.

Потім ці дані передаються в чергу (`chunk_queue`), де кожен робочий потік отримує чанк і починає роботу.

Коли робочий потік отримує опис чанку даних, він зчитує дані з файлу в оперативну память.
Потім перетворює дані в бари потрібного таймфрейму і зберігає їх в тимчасовий файл `<output_dir>/tmp/<SYMBOL>_<TIMEFRAME>.NNN.tmp` (наприклад: EURUSD_1m.001.tmp), де `NNN` - номер чанку.
Після завершення перетворення, головний потік збирає всі тимчасові файли в директорії `<output_dir>/tmp` і зберігає фінальний файл `<output_dir>/<SYMBOL>_<TIMEFRAME>.csv`.
